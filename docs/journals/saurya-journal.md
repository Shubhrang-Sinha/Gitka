Sprint 4 (Week 4: Nov 5 – Nov 11, 2026) — Codebase Q&A, Hybrid Search & Indexing Worker

Sprint Goal: Deliver Codebase Q&A where every answer is tied to a specific commit. It is built on splitting code into chunks of limited size (without analyzing the code's structure), filtering out secrets, PostgreSQL full-text (keyword) search, and pgvector similarity search by meaning.

Nov 5 (Thu) — Sprint 4 Planning: Designed Increment 4 (Codebase Q&A) with Akshita (the migrations 030_codebase_index.sql and 042_qa_conversations_and_jobs.sql) and Shubhrang (worker leases and rate limits).
Nov 6–8 (Fri–Sun) — Codebase Indexer (web/lib/codebase-index.ts) & Worker (web/lib/qa-jobs.ts, web/scripts/qa-worker.ts): Built code that walks through every folder in a Git repository using Forgejo's /git/trees/{commit} and /git/blobs/{sha} APIs. Set strict limits (at most 200 files, 32 KB per file, 800 chunks, and chunks of 50 lines or 2400 characters), left out certain paths (secrets/, node_modules/, lockfiles), and used containsKnownSecret() (a pattern-based check, called regex) to remove known secrets before any piece of code is saved in Postgres or sent to OpenRouter. Made the replacement of an index happen all at once (atomically), so if re-indexing fails, the previous good index is kept.
Nov 9–10 (Mon–Tue) — Q&A Engine That Uses Tools (web/lib/codebase-qa.ts & /api/projects/[id]/qa): Built hybrid retrieval (finding the relevant code), which combines PostgreSQL tsvector full-text search (protected from empty (NULL) rankings with coalesce) with pgvector cosine similarity (matching by meaning) when QA_EMBEDDING_MODEL is set. Gave the OpenRouter Q&A model read-only tools (search, listPaths, readLines, at most 6 steps and 60 seconds) and file source links tied to a specific commit that open directly in Forgejo.
Nov 11 (Wed) — Sprint 4 Review & Retro: Showed how to ask questions in plain English about how a project is built, using indexed repositories, and how to click straight to the exact cited lines in Forgejo. Retro note: Wrapping the ts_rank calculation in coalesce() fixed the odd cases where a hybrid query found no exact keyword matches.
